## 0. 目的、数据和两个设计选择

### 目的

用论文的无监督方法（配对状态 → 微状态 → 滞后 τ 转移矩阵 → Infomap 聚类），看能否从 3D 轨迹中把 **quick circle（求偶）** 和 **attack（攻击）** 与其他帧分开。

### 数据

- K 组、P 组各 3 次实验，每次 1 雌（F）+ 2 雄（M1、M2），35 min，166 fps，3D 三节点（嘴、胸鳍点、尾），身份和头尾经过人工审核。
- 训练：K_1_1、K_1_2、P_1_1、P_1_2；测试：K_1_3、P_1_3。测试视频和训练视频是**同一批鱼**的第 3 次实验。
- BORIS 标注只在聚类之后用于评估：
  - `qc` = quick circle + incomplete qc + Courtship；
  - `att` = attack + attempted att + Dash；
  - `wrap`；
  - 其余行为（follow、chase、approach 等）记为 `unknown`，不参与评估。
  - qc 和 att 在 BORIS 中没有漏标，所以没有标注的报警就是误报。
- 标注量（BORIS bout 数，训练 / 测试）：

  | 配对 | qc | att | wrap |
  |---|---|---|---|
  | FM1 | 32 / 17 | 6 / 3 | 8 / 2 |
  | FM2 | 84 / 49 | 7 / 4 | 2 / 2 |
  | M1M2 | 3 / 0 | 89 / 54 | 0 / 0 |

### 为什么分析"一对鱼"，而不是三条鱼一起

1. **论文的方法本身是两条鱼的**：状态是两条鱼之间的距离和各自朝向对方的角度。
2. **要找的行为是两两之间的**：qc 是雄鱼对雌鱼，att 是雄鱼对雄鱼。BORIS 的 `who` 也是 X→Y 的形式，按配对分析可以直接和标注对应。
3. **合并多个实验，需要统一谁是"鱼 a"**（论文用"赢家 / 输家"排序）：
   - **FM 单元**：a 永远是雌鱼，b 是雄鱼；FM1、FM2 合并成一个状态空间。
   - **MM 单元**：现在**不是**按"被选中雄鱼"排序，而是两种顺序都放进去（对称化）。在 M1M2 这个副本里 a = M1，在 M2M1 副本里 a = M2，M1 / M2 只是审核时的编号。每一帧的状态仍然有方向，所以攻击者可以读出来：v3 中按簇判断攻击方向，测试视频正确率 74–86%。按"被选中 = a"排序（对应论文的赢家 / 输家）还没做，见第 11 节。
4. **三条鱼一起分析是可行的**，取决于怎么设计状态，这是一个需要和导师讨论的设计选择：
   - 如果每对鱼都用完整的配对变量（3 个距离 + 6 个朝向角）并按现在的细度分格，状态会太稀。
   - 但可以用更紧凑的三鱼变量，例如：3 个两两距离（各 4 格）× 每条鱼朝向"三鱼中心"的角度（3 个，各 6 格）= 13824 个状态，和 v3 的 16129 同一量级。真实数据只占其中一部分组合（距离之间有三角不等式约束），而 Infomap 只处理出现过的状态。
   - 另一个做法：把每一帧三个配对各自所在的簇组合成"三鱼状态"。
   - 这次先做配对，是因为论文是配对、标注也是配对。**代价**：丢掉了第三条鱼的信息，例如雄鱼求偶时另一条雄鱼是否在旁边。

### 为什么 K、P 合并分析（KP），而不是只看 K 或只看 P

1. **数据量**：每组只有 2 个训练视频。分开分析的话每个单元约 140 万帧，而状态有 16129 个；合并后训练集每个被占用状态的中位数是 30 帧（第 5 节），分开就只剩一半左右。论文把 18 次实验合在一起。
2. **正例太少**：MM 的 qc 只出现在 P_1_1；FM 的 att 训练集只有 13 个 bout。单独一个组，很多类别根本无法评估。
3. **同一套簇才能比较组**：合并后 K 和 P 用同一套状态和簇，可以直接比较两组使用簇的比例（`04_usage`）。分开聚类得到两套不同的簇，无法对应。
4. **合并的风险**（需要讨论）：
   - 两组的标注者使用不同的词汇，例如 P 组有很长的 follow。
   - 两组是不同的个体。
   - 追踪模型的训练标注只来自 K_1_1 和 K_1_2，两组的追踪质量可能不同。

   以后可以做"用 K 训练、用 P 测试"的交叉检验。

**参数**

| 步骤 | 值 | 论文 |
|---|---|---|
| 去异常骨架 | 嘴–胸鳍 > 12 mm 或胸鳍–尾 > 25 mm → 这条鱼这一帧设为缺失 | 1.2 cm / 2.5 cm（斑马鱼） |
| 短缺口插值 | ≤ 5 帧，线性，不跨审核屏蔽的帧 | ≤ 5 帧，线性 |

| 来源 | 占比 |

| 审核时手动标为不可用的片段（每个视频 12–42 段） | 0.5–3.0% |
| 记录了身份交换的位置附近（交换所在的危险片段，或前后 0.5 s） | 0.4–2.5% |

审核时没看过的帧为 0。这些帧没有坐标，所以没有状态。

**图**：`00_skeleton__all__hpmax12-ptmax25-fill5-sw11-sph3__all.png`（骨架长度分布，对应论文 **Fig. S3D**）

**数据**：`data/00_cleaning__…csv`、`data/00_gap_table__…csv`（对应论文 **SI Table I**）

**结论**
- 异常骨架只占 0.02–0.06% 的鱼-帧。
- 插值补上了每个视频约 2000–2600 个鱼-帧（原缺失的 30–50%）。
- 有状态的帧占 92.9–96.4%；追踪丢失只有 0.1–0.6%，其余缺失都是审核屏蔽。

**和论文**：做法相同，平滑窗口按时间折算相近。

**需要讨论**
- 审核屏蔽集中在行为发生的地方：约一半的 wrap 帧、20% 的 MM att 帧没有状态。因为两鱼缠在一起时最容易发生身份交换。
- 打分时这些帧作为单独的一类，所以"有没有状态"本身就带有行为信息。
- 和 v3 比，清洗和平滑几乎没有改变后面的结果（第 7–9 节）。

|---|---|---|---|
| PC1 | 57.3% | 60.3% | **上下距离 Δz（r = −0.98）** |
| PC2 | 38.0% | 34.3% | 水平距离 D_xy（r = −0.96） |
| PC1 + PC2 | 95.3% | 94.6% | — |

**"我们的 PC1 是上下距离、论文的 PC1 是水平距离"的证据**
- **我们**：`00b_pca_physical_corr__FM__…`，PC1 与 Δz 的相关系数 −0.98，与 D_xy 只有 0.27；MM 也是 PC1 与 Δz −0.93。
- **论文**：正文 Fig. 2a 的说明写道，前两个模式"分别描述 XY 和 Z 方向上的分离"；SI Fig. S5 的说明写明 e1 是 x′（水平）距离，e2 是 z′（上下）距离。

**和论文一样的地方**
- 同样分成"2 个距离 + 朝向 + 俯仰 + 姿态"几组。
- 俯仰的两个模式（同号、反号）和论文的 e7、e8 对应。

**和论文不一样的地方**
- **前两个 PC 的顺序相反。** 论文因为斑马鱼打斗基本在同一水平面（Fig. S6），去掉了上下距离；我们必须保留。
- 论文的姿态模式（PC9–14）有可见的方差，我们几乎为 0。

**需要讨论**
- 姿态方差几乎为 0，可能是 3D 重建对骨架形状约束很强，把身体弯曲抹平了。这会影响"身体弯曲"能不能作为变量（v4 用了它）。
- PCA 只用来选变量，状态没有用 PC。理由：方差大不等于和行为有关；角度是环形量；MM 需要交换对称；状态要能解释。这和论文的做法一致。

## 3. ACF（自相关，时间尺度）

**参数**：每个变量在连续片段内计算，最大滞后 5 s；用 1/e 时间表示时间尺度。

**图**：`00b_pca_acf__…`（PC 的 ACF）、`01_acf__FM__dmax40-bd6-of-bz4-bth8-bs3-ct-minv0__train.png`、`01_acf__MM__…`（状态变量的 ACF）

**数据**：`data/00b_pca_acf__…csv`、`data/01_acf_times__…csv`

**结论**

| | 1/e 时间 |
|---|---|
| 距离（PC1、PC2；D_xy、Δz） | > 5 s（只有 MM 的 D_xy 是 4.6 s） |
| 朝向（PC3–6；cos θ、sin θ） | 1.2–2.1 s |
| 俯仰（PC7–8） | 0.8–1.4 s |
| 速度（log v） | 1.1–2.9 s |

**和论文一样**：距离最慢、朝向较快、姿态最快。所以和论文一样，状态保留距离和朝向。

**和论文不一样**：我们另外加了速度，它的时间尺度和朝向差不多。

**需要讨论**
- 距离的时间尺度超过 5 s，而 qc 只有 1–4 s，att 不到 0.1 s。慢变量决定了大簇，这可能是大簇按距离划分、和行为不对应的原因之一。
- 要捕捉短行为，可能需要更快的变量，例如 v4 里的转向速度、接近速度（第 10 节）。

## 4. 选择物理量（状态变量）

**状态**：s = (D_xy, Δz, θ_a, θ_b, v_a, v_b)，另加一个 contact 状态。

设 p 为胸鳍点、h 为嘴，下标 a、b 是两条鱼（FM：a = 雌鱼；MM：a = 副本里的第一条雄鱼）：

| 变量 | 含义 | 定义 | 单位 |
|---|---|---|---|
| D_xy | 水平距离 | 两个胸鳍点在水平面上的距离 ‖(p_b − p_a)_xy‖ | mm |
| Δz | 上下距离（带符号） | z(p_a) − z(p_b)；正 = a 在上 | mm |
| θ_a | a 的相对朝向（带符号） | 水平面上，从"a 指向 b"（p_b − p_a）转到"a 的头向"（h_a − p_a）的角度；0 = 朝向对方，±π = 背向对方，正 = 逆时针 | rad |
| θ_b | b 的相对朝向（带符号） | 同上，从 p_a − p_b 转到 h_b − p_b | rad |
| v_a、v_b | 每条鱼的速度 | 胸鳍点的 3D 速度，中心差分 ±3 帧（靠近缺口时用更短的差分） | mm/s |
| contact | 贴得太近 | 胸鳍水平距离 < 1 mm 或某条鱼几乎竖直（头–胸鳍水平长度 < 1 mm），角度无定义 → 一个单独的状态 | — |

MM 交换两条鱼时：(D_xy, Δz, θ_a, θ_b, v_a, v_b) → (D_xy, −Δz, θ_b, θ_a, v_b, v_a)，是状态之间严格的一一对应。

**结论**：v3b 训练集 95.0% 的帧有状态，其中 contact 约 0.8%（FM）。

**和论文**：论文是 (D_PP, θ_W, θ_L)，θ 的定义和我们相同。不同之处：
- 距离拆成水平 D_xy 和带符号的上下 Δz（论文是 3D 距离 D_PP）；
- 加了速度；
- 加了 contact 状态。

**需要讨论**
- 速度是在 Infomap **之前**放进状态的，分格边界只由速度分布决定，不看标注。
- 论文的整体转速 φ̇（两鱼连线的旋转速度）只用来解释"绕圈"，没放进状态；v4 把它作为"绕圈速度"放进了状态（第 10 节）。

- `MIN_STATE_VISITS = 0`：只要出现过的状态都进转移图，一帧不丢。

## 6. 转移矩阵

**参数**
- 滞后 τ：扫描 1, 2, 3, 5, 7, 10, 14, 17, 20, 25, 30, 40, 50, 70, 100, 124, 166 帧（0.006–1 s）。
- 完整分析的 τ：固定的 7、17 帧，加上第 7 节选出的 τ。FM：7、17、25、50；MM：7、17、20。
- (t, t+τ) 两帧都有状态、并且在同一个连续片段内，才计数。
- 4 个训练实验、每个单元的 2 个副本合成一个矩阵。保留自转移，按行归一化。

**图**：`03_state_block__FM__tau7-dmax40-bd6-of-bz4-bth8-bs3-ct-minv0__train.png` 等（按簇排序的状态级转移矩阵，对应论文 **Fig. 5a 中**）、`03_cluster_matrix__…`（簇到簇的转移）

**数据**：`data/03_within_summary__…csv`

**结论**
- 簇内转移占比（去掉对角线）0.26–0.37；把簇标签打乱后只有 0.001。说明转移矩阵确实有块状结构，并不是随便切出来的。
- 但这个占比比 v4 低一半（v4 是 0.70–0.76，第 10 节）。

**和论文**：构造方法相同。论文的 τ = 10 帧（100 fps，0.1 s）；我们的 0.1 s 相当于 17 帧。

**需要讨论**：166 fps 下相邻帧几乎不变，小 τ 时转移矩阵以自转移为主。

## 7. Infomap 聚类和 τ 的选择

**参数**
- python-igraph `community_infomap`（同论文）；τ 扫描时每个 τ 跑 50 次，完整分析跑 200 次（论文 500 次）；随机种子 20261107。
- τ 的选择：
  1. **论文规则**：最大簇的状态占比随 τ 突然跳变之前的 τ（论文 **Fig. S11a**）；
  2. **新增**：训练集留一实验交叉验证（LOEO）AUC 最高的 τ，每个类别各选一个。

**图**
- `03a_tau_scan__FM__dmax40-bd6-of-bz4-bth8-bs3-ct-minv0__train.png`、`…MM…`：左 = 论文规则曲线（对应 **Fig. S11a**，插图 = 簇数随 τ 变化）；右 = LOEO AUC 随 τ 变化，虚线 = 只用距离的基线。

## 8. 找出行为时段

**论文的做法**（Fig. 3、S8）：无监督。在 1 分钟窗口内计算 P(D, θ₁+θ₂, |θ₁−θ₂|)，用 Jensen-Shannon 距离做层次聚类，分出"打斗"和"非打斗"两类时段（每段几分钟）。

**我们的做法**：qc（1–4 s）和 att（< 0.1 s）太短，1 分钟窗口分不出来，所以改用 BORIS 标注给簇打分，再自动检测：
1. 用训练集计算每个簇的 P(行为 | 簇)，向整体比例收缩（加 50 个伪帧）。没有状态的帧单独算一类。
2. 帧分数 = 所在簇的分数，在同一配对内做居中滑动平均；窗口 = 行为时长的下限：qc、wrap 124 帧（0.75 s），att 5 帧。
3. 阈值：训练集上 F1 最大的值，测试集固定使用。
4. 对照：同样的流程，把"簇"换成 3D 胸鳍距离的 2 mm 格子（"只用距离"的基线）。

**参数**：`PRIOR_FRAMES` = 50；`SMOOTH_FRAMES` = qc 124、att 5、wrap 124；`DIST_BIN_MM` = 2；测试视频 = K_1_3、P_1_3。

**图**

- `05_score_hist__…`：测试集分数在正例和负例中的分布，竖线 = 阈值。

## 9. 选出"机动"：集中度和纯度

**论文的做法**（Fig. S11b）：56 个簇按"在打斗时段出现的频率"排序，前 16 个覆盖 95% 的打斗帧，合并左右对称后得到 10 种"打斗机动"（攻击、接近、绕圈、display 等，Fig. S12）。

**我们的做法**：同样的排序，只是把"打斗时段"换成 BORIS 的 qc / att 帧；另外加上论文没有的**纯度**（这些簇里有多少帧真的是该行为）。测试集沿用训练集的排序。

**参数**：覆盖比例 50% / 80% / 95%；按纯度排序时向整体比例收缩 50 帧。

**图**（文件夹 `Z:\medaka\runs\behavior_features\outputs\20261108_cluster_concentration_v2v3v3bv4\figures\`）

- `02_purity_recall__FM__base__all.png`、`…MM…`：簇按纯度逐个加入时的召回率和纯度

**Notebook**：`20261108_KP_cluster_concentration.ipynb`

**和论文不一样**：论文的打斗时段能被 16 个可命名的簇覆盖 95%；我们的 qc 要么被大簇吞掉，要么分散在很多小簇里。

- 逐帧检测能做到约 0.45 的精确率，靠的是 0.75 s 的平滑（相当于看一串连续的簇），而不是某个纯簇。这说明 qc 更像"簇的序列"。
- 论文没有对机动的顺序建模，只看分钟级窗口内各机动的出现概率（Fig. 6b、7b）。对我们的短行为，需要论文之外的一步，例如簇到簇的转移，或 1–2 s 窗口内簇的组成和顺序。
- 分层 Infomap（官方 `infomap` 包，已安装）可以检查 qc 是否是"近距离"大簇下面的一个子模块。

## 11. 总结

### 现在有的结果

1. **论文的结构在青鳉上同样存在**：PCA 分成距离、朝向、俯仰、姿态几组；时间尺度上距离最慢、朝向较快。区别是青鳉的第一主成分是上下距离（r = −0.98），所以必须保留 Δz。
2. **转移矩阵有真实的块状结构**：簇内转移远高于打乱参照，训练集的簇能覆盖 99% 以上的测试帧。
3. **但簇比论文碎得多**：v3b 有 1200–1900 个，论文是 56 个；而且最大簇没有论文那样的跳变。清洗和平滑没有改善这一点。行为没有对应的簇：qc 要么被"近距离"大簇吞掉，要么分散在很多小簇里。
4. **用簇打分可以检测行为，而且比只用距离好**（v3b）：
   - FM qc：精确率 0.42–0.48（距离 0.13），误报约为距离方法的 1/3–1/10。
   - MM att：AUC 0.965（距离 0.928）。
   - 但精确率还不够直接用于计数；FM 的 att 检测不到；wrap 用距离更好。
5. **v4（更快的变量、更粗的分格）让簇稳定得多**（等效簇数约 30–150，ARI 最高 0.99），qc 检测也略好，但 att 变差。
6. **攻击方向可以从簇读出**（v3，测试视频正确率 74–86%）。
7. **初步观察（只根据 BORIS 人工标注）**：被选中雄鱼 = 和雌鱼 wrap、雌鱼在这次 wrap 中产卵的那条雄鱼。

   | 视频 | 被选中雄鱼 | 攻击主要由谁发起（BORIS 攻击帧） |
   |---|---|---|
   | K_1_1 | M2 | M2（343 : 0） |
   | K_1_2 | 不确定（产卵时 M1、M2 都在 wrap） | M2（348 : 30） |
   | K_1_3 | M2 | M2（79 : 49） |
   | P_1_1 | M1 | M1（244 : 0） |
   | P_1_2 | 没有产卵 | M1（249 : 28） |
   | P_1_3 | M2 | M1（345 : 73） |

   3 个视频里被选中雄鱼也是主要攻击者，P_1_3 相反。每种情况只有 1–2 个视频，只能算描述。

### 需要改进的地方

1. **状态设计**：v3b 的簇太碎，v4 的簇稳定但 att 变差。需要找到兼顾两者的设计，例如 v4 加回速度、缺尾点时不丢状态；再用分层 Infomap 看层级结构。
2. **短行为需要序列层面的特征**：例如簇转移，或 1–2 s 窗口内簇的组成，这是论文之外的一步。
3. **按角色分析**：
   - att 按"被选中 / 未被选中雄鱼"分方向评估；
   - MM 改为"被选中 = a"建状态空间，对应论文的赢家 / 输家。
   - 需要先定 K_1_2（两条雄鱼同时 wrap）和 P_1_2（没有产卵）怎么处理。
4. **第三条鱼**：设计三鱼状态（例如 3 个距离 + 3 个朝向，约 1.4 万个状态），或者把三个配对每一帧的簇组合起来，回答"求偶时另一条雄鱼在做什么"。
5. **标注一致性**：K、P 两组的词汇不同；chase 目前算作 unknown，影响 att 的评估。
6. **泛化**：测试视频和训练是同一批鱼；需要新个体，以及"用 K 训练、用 P 测试"的检验。
7. **wrap 和审核屏蔽**：一半的 wrap 帧没有坐标，需要看能否减少屏蔽，或者单独处理。
